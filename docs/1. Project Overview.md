# Project Overview

## What is Ops-Pilot?

Ops-Pilot is a command-line operator for safely processing Renovate dependency-update pull requests in a Flux GitOps repository. It assesses each update, merges safe changes one at a time, watches Flux reconciliation, and diagnoses, repairs, or reverts a deployment that becomes unhealthy.

It automates the mechanical workflow in Go while reserving configuration-sensitive or uncertain decisions for an AI-assisted operator discussion. A proposed configuration change is always shown as an exact diff and requires explicit approval before it is committed and reassessed.

## Core Purpose

Ops-Pilot makes routine dependency updates less risky without treating a green pull request as proof that a running cluster will stay healthy. Its safety model is deliberately operational:

- process one eligible Renovate pull request at a time;
- assess release notes, repository manifests, and upstream evidence before merging;
- require operator involvement for major bumps, uncertainty, and configuration changes;
- compare Flux and workload health before and after a merge;
- repair only approved, allowlisted paths, then reassess; and
- revert a failed update when no approved repair can restore health.

The local checkout is read-only from the operator's point of view: repository writes use the GitHub API, and Flux reconciliation is triggered through the Kubernetes API.

## Technology Stack

- **Language:** Go 1.26.5
- **Module:** `github.com/lkshrk/ops-pilot`
- **CLI:** [Cobra](https://github.com/spf13/cobra)
- **GitOps and Kubernetes:** Flux controller API packages and Kubernetes `client-go`
- **AI integration:** OpenAI-compatible HTTP client, including streamed terminal discussion output
- **Terminal interaction:** `golang.org/x/term` and `github.com/creack/pty`
- **Configuration:** YAML v3
- **History:** SQLite through `modernc.org/sqlite`
- **Tests:** Go's built-in testing package, including end-to-end and adapter tests

## Key Features

- Finds and filters open Renovate dependency-update pull requests.
- Resolves changelogs from pull-request metadata, OCI annotations, configured overrides, or AI-assisted lookup.
- Classifies version bumps and uses AI evidence to assess deployment impact.
- Opens an interactive, streamed terminal discussion when an update is uncertain or configuration needs clarification.
- Applies only separately approved configuration diffs within configured allowlisted paths, then reassesses the updated pull request.
- Merges safe updates, triggers Flux, and observes Flux objects, workloads, events, and pod logs.
- Diagnoses failures, proposes an approved repair when possible, otherwise reverts and labels the pull request to prevent repeat attempts.
- Records run and attempt history in SQLite without making history a decision gate.
- Supports dry-run, non-interactive, single-pull-request, quiet, and verbose execution modes.

## Project Structure

```text
cmd/ops-pilot/          CLI entry point
internal/
  adapters/             GitHub, Flux, Kubernetes, OCI, HTTP, and Renovate adapters
  ai/                   AI contracts and OpenAI-compatible implementation
  changelog/            Changelog resolution and configured overrides
  checkout/             Read-only local repository workspace
  cli/                  Cobra commands and terminal approval/chat interaction
  cluster/              Flux and workload health observation
  composition/          Production dependency assembly
  config/               YAML configuration, defaults, and validation
  diagnostics/          Safe diagnostics and secret redaction
  domain/               Core pull-request, assessment, and health models
  history/              SQLite run and attempt persistence
  patch/                Validation and application of approved diffs
  run/                  Pull-request processing and safety workflow
configs/                Example configuration
docs/                   Install, configuration, CLI, and architecture documentation
test/e2e/               End-to-end workflow coverage
```

The executable starts at [`cmd/ops-pilot/main.go`](../cmd/ops-pilot/main.go), which delegates command construction to `internal/cli`; `internal/composition` wires production adapters into the `internal/run` orchestrator.

## Architecture Summary

Ops-Pilot is a single Go CLI with a layered architecture. The CLI loads and validates configuration, the composition layer creates concrete GitHub/Kubernetes/Flux/OCI/HTTP/AI adapters, and the run layer coordinates the domain workflow through ports. This keeps safety decisions and orchestration testable without live infrastructure while confining network and cluster effects to adapters.
